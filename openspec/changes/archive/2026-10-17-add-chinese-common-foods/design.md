## Context

食物库种子 `SEED_FOODS`（src/services/foodService.ts）现有 33 条，偏欧美健康轻食语境。数据结构已完备：双语 name/name_en、双语 notes/notes_en、per-100g 营养、可选 gi、可选 portions（JSON 双语份量锚点）。「种子食物升级补齐」机制（canonical 中文名匹配、仅插缺失、不覆盖用户行）已在生产验证（白米饭/鹰嘴豆、牛奶/酸奶/土豆/香蕉/苹果两轮扩充均复用）。无需任何 schema 迁移。

## Goals / Non-Goals

**Goals:**

- 一次数据增量：SEED_FOODS 追加 19 条中国家常食物（33 → 52），新装与覆盖升级两条路径均自动生效
- 营养值采用《中国食物成分表》优先口径，USDA 兜底；熟重/可食部口径在名称或备注标注
- 中式生活化份量锚点（按个/按碗/按根），Quick Log 份量模式开箱即用

**Non-Goals:**

- 家常混合菜（番茄炒蛋、鱼香肉丝等）：烹饪用油差异过大，营养值不可信，不纳入
- 调味品（盐/酱油/醋）：单次用量小且难以估算，不纳入
- 新增分类、新增字段、UI 改动：分类 Pills 五类不变，数据结构零变更

## Decisions

### D1：纯数据增量，复用既有补齐机制

SEED_FOODS 数组末尾新增一个注释分区 `// —— 中国家常食物 ——`（内部按分类再分小注释），每条自带 category_zh。缺失插入/幂等/跳过分类缺失全部由既有 `ensureSeedFoods` 承担，零逻辑改动。

备选：给家常食物单独建「中国菜」分类——否决，破坏既有 5 分类 Pills 语义与语义标签派生规则（标签依赖分类）。

### D3：与未归档 modernize 变更的关系

modernize-diet-tracker-experience 对 everyday foods 走的是 ADDED 需求路线（鸡蛋/奶/水果已覆盖），本变更同为 ADDED（中国家常食物数据集），两者互不覆盖、归档顺序无关。本变更不 MODIFIED 任何既有需求。

### D4：升级回填无需改动

新 19 条在旧库中不存在 → 走「缺失插入」路径完整写入（含 portions）；「portions NULL 回填」路径只对已存在行生效，与新增条目无交集，allowlist 无需扩充。

## Risks / Trade-offs

- [营养值为参考值，来源间存在差异] → 与既有 33 条同一标准：口径标注 + 备注提示，不做精确承诺
- [份量锚点（1 个馒头 100g 等）因地区/大小而异] → 沿用既有生活化锚点风格（鸡胸 1 掌心 100g 同精度），主锚点选中等大小，用户可切克数模式
- [覆盖安装用户曾删除种子分类] → 既有机制跳过该条不中断（主 spec 已有场景），不做额外处理
- [水饺/面条等加工食品品牌差异] → 名称标注（熟）/（水煮口径），备注注明参考值；录错可编辑，影响可控
- [数量护栏测试过期风险] → 同步更新 tests/foodLibrary.test.ts 护栏窗口（49–53），并补营养值/portions 断言

## Migration Plan

纯种子数据增量，无迁移。发布随常规版本（versionCode +1）；回滚 = revert 提交即可，已插入的种子行无害（用户可手动删除，或接受保留）。

## Open Questions

无阻塞性未知。五花肉等高脂食物是否需要 UI 提示仅靠 notes 文案（不做特殊 UI 标记）——采用 notes 方案，已定。
